# Self-hosting

Jackline ships as separate containers (**api**, **gateway**, **web**, **docs**, plus Postgres). How you put an edge in front of them is up to you.

**Default:** one origin via Caddy (admin UI + API + MCP together — simplest cookies/CORS).  
**Optional:** split the gateway for scale/exposure, or skip Caddy and use your own proxy.

Public URLs are the contract: set `WEB_ORIGIN`, `BETTER_AUTH_URL`, `JACKLINE_PUBLIC_API_URL`, and `JACKLINE_PUBLIC_MCP_URL` to whatever browsers and MCP clients actually call. Cursor should use `JACKLINE_PUBLIC_MCP_URL`.

## Production (recommended default)

Same-origin edge with Caddy:

```bash
cp deploy/.env.prod.example .env.prod
# set JACKLINE_MASTER_KEY and BETTER_AUTH_SECRET (openssl rand -base64 32)

docker compose -f deploy/compose.prod.yml --env-file .env.prod up --build -d
```

| URL | Service |
| --- | --- |
| http://localhost/ | Admin UI (`/api`, `/mcp` on the same origin) |
| http://docs.localhost/ | Docs |
| http://localhost/openapi.json | OpenAPI JSON |
| http://localhost/health | API health |

Clone + build is intentional for open source — no registry pull required.

### HTTPS on a real domain

1. Point DNS for your app host and docs host at the machine (ports **80** and **443** reachable).
2. In `.env.prod`, use **bare hostnames** for Caddy site addresses (no `http://`) so Caddy enables HTTPS:

```bash
JACKLINE_SITE_ADDRESS=jackline.example.com
JACKLINE_DOCS_SITE_ADDRESS=docs.jackline.example.com
JACKLINE_CADDY_GLOBAL_OPTIONS=email you@example.com

WEB_ORIGIN=https://jackline.example.com
BETTER_AUTH_URL=https://jackline.example.com
JACKLINE_PUBLIC_API_URL=https://jackline.example.com
JACKLINE_PUBLIC_MCP_URL=https://jackline.example.com/mcp
```

3. Recreate: `docker compose -f deploy/compose.prod.yml --env-file .env.prod up -d`

Certificates persist in the `caddy_data` volume.

## Topology recipes

### Gateway split (data plane separate)

Publish MCP on its own port/host; Caddy serves UI + API only:

```bash
docker compose -f deploy/compose.prod.yml -f deploy/compose.gateway-split.yml \
  --env-file .env.prod up --build -d
```

Set `JACKLINE_PUBLIC_MCP_URL` to the gateway URL clients should use (e.g. `https://mcp.example.com/mcp` behind your TLS terminator, or `http://127.0.0.1:8081/mcp` locally). `JACKLINE_GATEWAY_PUBLISH_PORT` defaults to `8081`.

### Bring your own edge

No Jackline-managed proxy — ports published for your nginx / Traefik / cloud LB:

```bash
docker compose -f deploy/compose.prod.yml -f deploy/compose.byo-edge.yml \
  --env-file .env.prod up --build -d
```

| Publish port env | Default | Container |
| --- | --- | --- |
| `JACKLINE_API_PUBLISH_PORT` | 8080 | api |
| `JACKLINE_GATEWAY_PUBLISH_PORT` | 8081 | gateway |
| `JACKLINE_WEB_PUBLISH_PORT` | 8088 | web |
| `JACKLINE_DOCS_PUBLISH_PORT` | 8089 | docs |

Route externally however you like. Same-origin UI+API remains the easiest for session cookies; if the UI and API are on different hosts, set `WEB_ORIGIN` to the UI origin and `BETTER_AUTH_URL` / `JACKLINE_PUBLIC_API_URL` to the API origin. Use `JACKLINE_ADDITIONAL_ORIGINS` (comma-separated) for any extra browser origins.

Suggested long-term shape: **gateway** on its own host when you care about scale/exposure; **UI + API** as the control plane (together by default).

## Dev Compose

Hot-reload stack (`tsx` / Vite):

```bash
cp .env.example .env
docker compose -f deploy/docker-compose.yml up --build
```

| Service | Port |
| --- | --- |
| Postgres | 5433 → 5432 |
| API | 8080 |
| Gateway | 8081 |
| Admin UI | 5173 |
| Docs | 3000 |

## Local development (no Docker)

```bash
pnpm install
cp .env.example .env
pnpm db:migrate
pnpm dev          # api + web + gateway
pnpm docs:dev     # Zudoku on :3000 (exports OpenAPI first)
```

## Regenerating the API reference

```bash
pnpm openapi:export   # writes apps/docs/apis/openapi.json
pnpm docs:dev         # or docs:build
```

`docs:dev` runs the export automatically via `predev`. Commit an updated `openapi.json` before building production docs images.
