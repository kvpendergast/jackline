title: Authentication

The Jackline Admin API (`/api/v1`) supports two auth modes on the **same routes**:

| Caller | Auth |
| --- | --- |
| Admin UI / browsers | Better Auth **session cookie** + `X-Jackline-Tenant-Id` |
| Machines / SDKs / CI | OAuth2 **client_credentials** → Bearer access token |

## OAuth2 client credentials

1. Create a **service** client in the admin UI (Clients) or via the API.
2. Mint credentials: `POST /api/v1/clients/{id}/credentials` (session required). Store `client_secret` — it is shown once.
3. Exchange for an access token:

```bash
curl -sS -X POST http://127.0.0.1:8080/api/v1/oauth/token \
  -H 'content-type: application/x-www-form-urlencoded' \
  -d "grant_type=client_credentials&client_id=$CLIENT_ID&client_secret=$CLIENT_SECRET"
```

Response:

```json
{
  "access_token": "jackline_at_…",
  "token_type": "Bearer",
  "expires_in": 3600
}
```

4. Call the Admin API:

```bash
curl -sS http://127.0.0.1:8080/api/v1/servers \
  -H "Authorization: Bearer $ACCESS_TOKEN"
```

Tenant is taken from the token. If you also send `X-Jackline-Tenant-Id`, it must match.

### Rotate / revoke

- `POST /api/v1/clients/{id}/credentials` — rotate secret; revokes outstanding access tokens
- `DELETE /api/v1/clients/{id}/credentials` — clear secret and revoke tokens

## CLI login (user tokens)

`jackline login --server https://jackline.example.com` signs the CLI in as **you** — no API key to paste. It uses the same authorization server as MCP OAuth, with a different audience:

1. The CLI reads `/.well-known/oauth-authorization-server` (`jackline_api_resource`, `jackline_cli_client_id`, `jackline_tenancy`).
2. It listens on `http://127.0.0.1:<random port>/callback` and opens `GET /oauth/authorize` with `client_id=jackline-cli`, PKCE (`S256`), and `resource=<api base>/api/v1`. You sign in and approve in the browser.
3. `POST /oauth/token` returns a **15-minute** `jackline_uat_…` access token and a `jackline_urt_…` refresh token. The CLI keeps both in the OS keychain.

| | |
| --- | --- |
| Client | Pre-registered public client `jackline-cli` (no secret, PKCE required). Loopback redirects on any port (RFC 8252). |
| Access token | `jackline_uat_…`, 15 min, bound to one tenant and user. Role is read from the membership on every request, so a `member` stays a `member`. |
| Refresh token | `jackline_urt_…`, single use, rotated on every refresh; expires after 30 days without use. Reusing an old one revokes the login. |
| Revoke | `POST /oauth/revoke` (`token`, `client_id=jackline-cli`), used by `jackline logout`. |
| Multi-tenant servers | Pass `tenant=<slug>` (CLI: `--tenant`). |

Audiences are kept apart: `jackline_uat_` tokens are rejected by the MCP gateway, and `jackline_mcp_` tokens are rejected by `/api/v1`. Third-party MCP clients (CIMD / DCR) cannot request the API resource. `GET /api/v1/me` with a user token returns the user, the token's tenant and role (`current`), and the deployment's `mcpUrl`.

## Session cookies

Used by the admin UI. Sign up / sign in via Better Auth (`/api/auth/*`), then send `X-Jackline-Tenant-Id` on tenant-scoped routes.

## Gateway MCP tokens

Connection credentials (`jkl_…`) authenticate the **MCP gateway**, not the Admin API. Do not reuse them for `/api/v1`.

For OAuth-based MCP hosts (CIMD / DCR), see [MCP OAuth](/mcp-oauth). Those flows mint `jackline_mcp_…` tokens at `POST /oauth/token` (not `/api/v1/oauth/token`).
