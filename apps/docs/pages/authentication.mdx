# Authentication

The Mesh Admin API (`/api/v1`) supports two auth modes on the **same routes**:

| Caller | Auth |
| --- | --- |
| Admin UI / browsers | Better Auth **session cookie** + `X-Mesh-Tenant-Id` |
| Machines / SDKs / CI | OAuth2 **client_credentials** → Bearer access token |

## OAuth2 client credentials

1. Create a **service** client in the admin UI (Clients) or via the API.
2. Mint credentials: `POST /api/v1/clients/{id}/credentials` (session required). Store `client_secret` — it is shown once.
3. Exchange for an access token:

```bash
curl -sS -X POST http://127.0.0.1:8080/api/v1/oauth/token \
  -H 'content-type: application/x-www-form-urlencoded' \
  -d "grant_type=client_credentials&client_id=$CLIENT_ID&client_secret=$CLIENT_SECRET"
```

Response:

```json
{
  "access_token": "mesh_at_…",
  "token_type": "Bearer",
  "expires_in": 3600
}
```

4. Call the Admin API:

```bash
curl -sS http://127.0.0.1:8080/api/v1/servers \
  -H "Authorization: Bearer $ACCESS_TOKEN"
```

Tenant is taken from the token. If you also send `X-Mesh-Tenant-Id`, it must match.

### Rotate / revoke

- `POST /api/v1/clients/{id}/credentials` — rotate secret; revokes outstanding access tokens
- `DELETE /api/v1/clients/{id}/credentials` — clear secret and revoke tokens

## Session cookies

Used by the admin UI. Sign up / sign in via Better Auth (`/api/auth/*`), then send `X-Mesh-Tenant-Id` on tenant-scoped routes.

## Gateway MCP tokens

Connection credentials (`msh_…`) authenticate the **MCP gateway**, not the Admin API. Do not reuse them for `/api/v1`.
