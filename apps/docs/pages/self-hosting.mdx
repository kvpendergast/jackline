title: Self-hosting

**Primary path:** generic Docker Compose with Postgres in the stack.  
**Recipes** below swap the database, edge proxy, or cloud provider without changing the product model.

Jackline runs as **api**, **gateway**, **web**, and **docs**. Public URLs are the contract: set `WEB_ORIGIN`, `BETTER_AUTH_URL`, `JACKLINE_PUBLIC_API_URL`, and `JACKLINE_PUBLIC_MCP_URL` to what browsers and MCP clients actually call. Cursor uses `JACKLINE_PUBLIC_MCP_URL`. In-product Chat uses `JACKLINE_INTERNAL_MCP_URL` (Compose default `http://gateway:8081/mcp`).

## Quick start (generic Docker)

Hot-reload stack for trying Jackline on one machine (Postgres included):

```bash
cp .env.example .env
# Required:
#   POSTGRES_PASSWORD=…
#   JACKLINE_MASTER_KEY=$(openssl rand -base64 32)
#   BETTER_AUTH_SECRET=$(openssl rand -base64 32)

pnpm env:check   # optional — fail fast on missing env
docker compose -f deploy/docker-compose.yml up --build
```

| Surface | URL |
| --- | --- |
| Admin UI | http://127.0.0.1:5173 |
| API | http://127.0.0.1:8080 |
| Gateway MCP | http://127.0.0.1:8081/mcp |
| Docs | http://127.0.0.1:3000 |
| Postgres (host) | `127.0.0.1:5433` |

## Production images (generic Docker)

Multi-stage images (`deploy/Dockerfile`) are published to **GitHub Container Registry** (`ghcr.io/kvpendergast/jackline-*`) on every `main` push and on `v*` tags. Compose still includes `build:` so `up --build` works offline.

**Include Postgres** with the overlay (default self-host story):

```bash
cp deploy/.env.prod.example .env.prod
# set JACKLINE_MASTER_KEY, BETTER_AUTH_SECRET, POSTGRES_PASSWORD

docker compose -f deploy/compose.prod.yml -f deploy/compose.postgres.yml \
  --env-file .env.prod pull
docker compose -f deploy/compose.prod.yml -f deploy/compose.postgres.yml \
  --env-file .env.prod up -d
```

| URL | Service |
| --- | --- |
| http://localhost/ | Admin UI (`/api`, `/mcp` same origin) |
| http://docs.localhost/ | Docs |
| http://localhost/openapi.json | OpenAPI JSON |
| http://localhost/health | API health |

While the GitHub repo is private, GHCR packages default to **private** — either make each package Public in GitHub → Packages, or `docker login ghcr.io` before `pull`. Build from source anytime with `up --build`.

Pin or retarget images via `.env.prod`:

```bash
JACKLINE_API_IMAGE=ghcr.io/kvpendergast/jackline-api:sha-abcdef0
JACKLINE_GATEWAY_IMAGE=ghcr.io/kvpendergast/jackline-gateway:sha-abcdef0
# …
```

## Recipes

Start from the generic path, then change only what the recipe names.

### Mirror images to your registry

Enterprises often pull only from ECR / GCR / ACR / Harbor. Mirror once, then point Compose at your tags:

```bash
SRC=ghcr.io/kvpendergast
DST=123456789012.dkr.ecr.us-east-1.amazonaws.com
TAG=latest   # or sha-… / semver from GHCR

for name in api gateway web docs migrate; do
  docker pull "$SRC/jackline-$name:$TAG"
  docker tag  "$SRC/jackline-$name:$TAG" "$DST/jackline-$name:$TAG"
  docker push "$DST/jackline-$name:$TAG"
done
```

In `.env.prod`:

```bash
JACKLINE_API_IMAGE=123456789012.dkr.ecr.us-east-1.amazonaws.com/jackline-api:latest
JACKLINE_GATEWAY_IMAGE=123456789012.dkr.ecr.us-east-1.amazonaws.com/jackline-gateway:latest
JACKLINE_WEB_IMAGE=123456789012.dkr.ecr.us-east-1.amazonaws.com/jackline-web:latest
JACKLINE_DOCS_IMAGE=123456789012.dkr.ecr.us-east-1.amazonaws.com/jackline-docs:latest
JACKLINE_MIGRATE_IMAGE=123456789012.dkr.ecr.us-east-1.amazonaws.com/jackline-migrate:latest
```

### BYO Postgres

Omit `compose.postgres.yml`. Set `DATABASE_URL` in `.env.prod` to your managed DB (RDS, Cloud SQL, etc.):

```bash
docker compose -f deploy/compose.prod.yml --env-file .env.prod pull
docker compose -f deploy/compose.prod.yml --env-file .env.prod up -d
```

### GCP (Pulumi)

For a small always-on (or destroy-when-idle) instance on Google Cloud, see **[deploy/pulumi/README.md](https://github.com/kvpendergast/jackline/blob/main/deploy/pulumi/README.md)**:

- **Default:** single VM + production Compose + Cloud SQL
- **Advanced:** GKE Autopilot (higher idle cost)

CI can deploy on merge to `main` via Workload Identity Federation. Live VM updates go through `deploy/scripts/remote-deploy.sh` (rolling health check). Do not use `docker compose up --build -d` on an already-running production VM — that replaces containers in place.

### Gateway split (data plane separate)

Publish MCP on its own port/host; Caddy serves UI + API only:

```bash
docker compose -f deploy/compose.prod.yml -f deploy/compose.postgres.yml \
  -f deploy/compose.gateway-split.yml --env-file .env.prod up --build -d
```

Set `JACKLINE_PUBLIC_MCP_URL` to the gateway URL clients should use (e.g. `https://mcp.example.com/mcp`). `JACKLINE_GATEWAY_PUBLISH_PORT` defaults to `8081`.

### Bring your own edge

No Jackline-managed proxy — ports published for your nginx / Traefik / cloud LB:

```bash
docker compose -f deploy/compose.prod.yml -f deploy/compose.postgres.yml \
  -f deploy/compose.byo-edge.yml --env-file .env.prod up --build -d
```

| Publish port env | Default | Container |
| --- | --- | --- |
| `JACKLINE_API_PUBLISH_PORT` | 8080 | api |
| `JACKLINE_GATEWAY_PUBLISH_PORT` | 8081 | gateway |
| `JACKLINE_WEB_PUBLISH_PORT` | 8088 | web |
| `JACKLINE_DOCS_PUBLISH_PORT` | 8089 | docs |

If UI and API are on different hosts, set `WEB_ORIGIN` to the UI origin and `BETTER_AUTH_URL` / `JACKLINE_PUBLIC_API_URL` to the API origin. Use `JACKLINE_ADDITIONAL_ORIGINS` for extra browser origins.

### HTTPS on a real domain

1. Point DNS for your app host and docs host at the machine (ports **80** and **443** reachable).
2. In `.env.prod`, use **bare hostnames** for Caddy site addresses (no `http://`):

```bash
JACKLINE_SITE_ADDRESS=jackline.example.com
JACKLINE_DOCS_SITE_ADDRESS=docs.jackline.example.com
JACKLINE_CADDY_GLOBAL_OPTIONS=email you@example.com

WEB_ORIGIN=https://jackline.example.com
BETTER_AUTH_URL=https://jackline.example.com
JACKLINE_PUBLIC_API_URL=https://jackline.example.com
JACKLINE_PUBLIC_MCP_URL=https://jackline.example.com/mcp
```

3. Recreate the stack (keep `compose.postgres.yml` if you use bundled Postgres).

Certificates persist in the `caddy_data` volume.

## Local development (no Docker)

```bash
pnpm install
cp .env.example .env
# set secrets + DATABASE_URL / POSTGRES_*
pnpm env:check
pnpm db:migrate
pnpm dev          # api + web + gateway
pnpm docs:dev     # Zudoku on :3000
```

## Regenerating the API reference

```bash
pnpm openapi:export   # writes apps/docs/apis/openapi.json
pnpm docs:dev         # or docs:build
```

`docs:dev` runs the export automatically via `predev`. Commit an updated `openapi.json` before building production docs images.
